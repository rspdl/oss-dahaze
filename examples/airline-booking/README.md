# 항공 예약 시스템 데모

이 예시는 작은 CRUD 샘플보다 복잡한 항공 예약 도메인에서 dahaze가 무엇을 보여 주는지
시연한다. 정상 기준선 하나와, 그 기준선에서 실제 기획 과정에 생길 법한 결함을 하나씩 분리한
여섯 개의 반례로 구성되어 있다.

## 1. 정상 기준선

[`good.rspdl`](good.rspdl)은 rspdl 0.1.0에서 진단 없이 컴파일된다.

- 열거형 2개: 예약 상태, 결제 상태
- 데이터 모델 8개: 항공편, 예약, 승객, 운임, 결제, 좌석, 항공권, 환불
- 관계 8개와 cardinality·공존 규칙 5개
- 화면 21개에 걸친 생성·입력·조회·수정·삭제 lifecycle
- 값 제약 6개: 출발지/도착지 차이, 양수 금액과 좌석 수 등
- 역할 4개, 행동 4개, 허용·거부 정책 6개

먼저 이 파일을 새 프로젝트의 문서로 저장하고 컴파일한다. 진단이 없다는 것뿐 아니라 정책
검토 화면에서 역할·대상·필드·행동·효과를 필터링할 수 있다는 점까지 보여 주는 것이 정상
시연의 핵심이다.

## 2. 결함 주입 시나리오

각 파일은 하나의 질문에 집중한다. 문서를 하나씩 열어 컴파일한 뒤, 진단을 선택해 문제가 된
기획 문장으로 이동한다.

| 파일 | 기획 질문 | 기대 진단 |
|---|---|---|
| [`conflict-cancellation.rspdl`](conflict-cancellation.rspdl) | 예약 취소는 상태를 바꾸는가, 예약 자체를 지우는가? | `RSPDL-DATA-004` 행동 결과 충돌 |
| [`conflict-relation-rules.rspdl`](conflict-relation-rules.rspdl) | 예약자와 탑승객의 겸임을 허용하는가, 금지하는가? | `RSPDL-REL-004` 관계 규칙 충돌 |
| [`missing-payment-creator.rspdl`](missing-payment-creator.rspdl) | 결제 조회·수정·삭제 전에 결제는 어디서 생성되는가? | `RSPDL-DATA-001`, `RSPDL-DATA-002` 생산자 누락 |
| [`missing-ticket-number-producer.rspdl`](missing-ticket-number-producer.rspdl) | 발권된 항공권 번호는 누가 입력하거나 계산하는가? | `RSPDL-DATA-001` 필드 생산자 누락 |
| [`missing-fare-recalculation.rspdl`](missing-fare-recalculation.rspdl) | 운임이 바뀌면 예약 총액은 언제 다시 계산되는가? | `RSPDL-DATA-003` 재계산 누락, `RSPDL-DATA-W002` 집계 범위 미정 |
| [`conflict-total-producers.rspdl`](conflict-total-producers.rspdl) | 예약 총액은 사용자가 입력하는가, 시스템이 계산하는가? | `RSPDL-DATA-004` 복수 생산자 충돌 |

## 3. 권장 데모 순서

1. `good.rspdl`을 컴파일해 복잡한 기획도 구조화된 결과로 바뀌고 진단이 없음을 보여 준다.
2. 정책 검토 화면에서 `고객` 역할을 필터링해 허용과 거부 정책을 나란히 보여 준다.
3. 취소 결과 충돌 파일을 열어 같은 행동이 같은 예약에 수정과 삭제를 동시에 요구함을 보여 준다.
4. 결제 생성 경로 누락 파일로 “화면은 있는데 데이터가 태어나는 곳은 없음”을 보여 준다.
5. 항공권 번호 생산자 누락 파일로 모델 생성과 필드 값 생성이 서로 다른 문제임을 보여 준다.
6. 운임 재계산 누락 파일로 파생값의 원본과 갱신 시점까지 기획에 포함되어야 함을 보여 준다.
7. 총액 생산자 충돌 파일로 사람 입력과 시스템 계산 중 하나를 제품 결정으로 확정하게 만든다.

## 4. 현재 제품 경계

rspdl 0.1.0은 화면 간 순서·분기, 삭제 후 접근, 조건부 정책의 충돌·누락·도달 불가를 아직
한국어 문법과 컴파일 진단으로 연결하지 않는다. 따라서 이 데모는 그 기능을 지원하는 것처럼
연출하지 않는다. 현재 확실히 보여 줄 수 있는 강점은 데이터 lifecycle, 필드 provenance,
행동 mutation, 파생값 재계산, 관계 메타 규칙과 정책 표의 구조화다.
