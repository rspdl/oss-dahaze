# Planning Workspace Versions

## 배경

기획자는 인터뷰와 화면 검토를 반복하면서 여러 문서를 함께 바꾼다. 오류가 있는 초안도
다음 질문의 근거로 남아야 한다. 문서별 저장만으로는 변경 묶음을 원자적으로 적용하거나
개발자에게 전달했던 원문·환경·화면 배치를 함께 복원할 수 없다.

원문이 같아도 화면 배치와 결정 근거는 달라질 수 있다. 따라서 원문 리비전만 전달본의
식별자로 사용하면 서로 다른 전달본이 같은 버전으로 보인다.

## 결정

### 서로 다른 세 가지 버전

- 프로젝트 원문 리비전은 문서 생성·수정·삭제와 변경 묶음 적용 때 증가한다. 기존 문서
  편집 API도 이 규칙을 따른다. 경로와 원문으로 계산한 source hash를 함께 검사한다.
- 기획 상태 리비전은 대화·결정·보류·디자인·환경·샘플 데이터가 바뀌면 증가한다.
- 스냅샷 버전은 전체 프로젝트 상태를 캡처할 때마다 증가한다. 원문 리비전과 독립적이며
  원문 변경 없이 만든 전달본도 별도의 버전이다.

원문이 의미의 원본이다. 대화나 디자인 설정에 적힌 설명을 RSPDL 규칙으로 해석하지 않는다.
컴파일 JSON은 여전히 재생성 가능한 파생물이며 모델·필드·진단 테이블로 정규화하지 않는다.

### 초안 보관과 적용

변경안은 기준 원문 리비전/hash, 문서별 추가·수정·삭제, 후보 원문 전체, 컴파일 결과와
그 결과의 런타임 정체를 보관한다. 오류가 있는 후보의 보관은 확정 원문의 변경이 아니다.

AI 작업은 enqueue 시점의 기획 revision, 기준 원문 revision/hash, 선택 대상의 source path와
compiler stable ID를 frozen context로 보관한다. source draft를 고쳐 만든 초안은 그 draft의
원래 기준 revision/hash를 이어받는다. 작업 중 확정 원문이나 기획 상태가 바뀌면 결과를 버리지
않고 stale 검토 결과로 남기며, 최신 상태 위에 적용 가능한 것처럼 표시하지 않는다.

적용은 별도의 명시적 사용자 요청이다. 기준이 달라졌으면 충돌을 반환한다. compiler의
error 진단이 있으면 원문은 그대로 두고 미적용 상태와 원래 결과를 정상 응답으로 반환한다.
warning/info만으로 적용을 막지 않는다. 알 수 없는 결과 구조나 런타임 불일치를 검증 성공으로
처리하지 않는다. 비어 있는 프로젝트는 결과가 없는 상태로 명시적으로 다룬다.

프로젝트를 먼저 잠그고, 기획 상태와 문서를 일관된 순서로 잠근다. 여러 문서 변경,
문서별 이력, 프로젝트 리비전, 적용 전후 스냅샷은 같은 트랜잭션에 속한다. 중간 실패 시
모두 롤백하며 부분 적용을 남기지 않는다. 재요청으로 같은 초안을 두 번 적용하지 않는다.

### 캡처와 복원

스냅샷에는 실제 저장된 문서 식별자·경로·원문·대상 버전, 기획 상태, source hash,
compiler 버전·wire schema·locale, 당시 컴파일 결과를 담는다. 이후 편집은 기존 스냅샷을
수정하지 않는다. 디자인만 수정한 현재 상태도 명시적으로 캡처할 수 있다.

복원은 과거 기록을 덮어쓰지 않고 새 원문 리비전과 새 스냅샷을 만든다. 적용 전후와 마찬가지로
복원 직전 상태도 보관한다. 원문과 기획 상태의 예상 리비전을 모두 검사하므로 다른 탭의
디자인·대화 수정도 조용히 유실되지 않는다. 과거 compiler 결과는 당시 버전의 결과로
표시하며 현재 런타임에서 다시 검증한 결과로 표시하지 않는다.

### 전달 계약

읽기 전용 화면·다운로드·MCP는 같은 스냅샷 버전의 전체 프로젝트를 전달한다. 각 채널은
같은 application 유스케이스와 권한 검사를 사용한다. 미정 사항과 compiler 진단도 함께
전달하며 임의의 완료 점수나 준비 완료 판정을 만들지 않는다.

목록에는 버전과 요약을 제공하고 원문·컴파일 결과 전문은 선택한 버전에서 조회한다.
버전 비교는 원문과 사용자 작성 상태의 차이를 보여주며 의미상 충돌을 자체 판정하지 않는다.

## 검증과 한계

동시 편집, 중복 적용, 중간 저장 실패, 삭제 후 복원, 디자인만 수정한 상태의 캡처,
권한이 없는 사용자의 조회·변경을 회귀 검증한다. 이 ADR은 저장 계약이며 각각의 구현 완료
여부는 [구현·검수 기록](../plans/implementation-status.md)에서 추적한다.

오래된 compiler를 같은 프로세스에 추가로 적재하지 않는다. 과거 결과의 재생성이 필요하면
ADR-0002의 단일 버전/프로세스 계약에 따라 해당 버전의 별도 프로세스를 사용한다.
