# 기획 작업공간의 compiler 계약

## CURRENT — 2026-09-23

- 기획 작업공간이 사용하는 새 compiler 계약은 로컬 `533a542`까지 구현·통합 검수했다.
  검수한 rspdl-core 저장소 head는 `1387144`이며 core workspace, Node SDK, 라이선스,
  Python Linux wheel CI가 통과했다.
- dahaze 최종 검수 커밋 `b920651`의 전체 하네스는 API 215개 통과·3개 skip, web 201개,
  editor 46개와 타입 검사, lint, build, 경계·OpenAPI 검사를 통과했다. durable AI 작업의
  기준 커밋 `cafab42` 당시 API 하네스 214개 통과·3개 skip 기록도 역사적 통합점으로 남긴다.
  AI 작업 경쟁 조건 8개와 worker 복구 시나리오 5개도 별도 검수에서 통과했다.
- 최신 분리 프롬프트와 `gpt-5.4-mini`의 실제 종단간 저작 흐름을 검수했다. 첫 생성 작업
  `233eca`의 후보 `9aa9`에는 중복 ID `LINK003`과 중복 operation `DATA004`가 남았고,
  compiler 진단을 그대로 표시한 뒤 manual-only 정책을 인터뷰·채택했다. 같은 후보에서 다시
  생성한 작업 `ce733b15`의 초안 `a618e2d2`는 약 13초 만에 완료됐고 compiler 진단이 0건이었다.
  결과에는 IA, 화면 2개, 결과 2개, 경로 2개와 manual workflow가 있었으며 invented lookup은
  없었다. UI의 명시적 적용은 HTTP 200, `applied=true`로 프로젝트 revision 1을 만들었다.
- acquisition을 제거한 반례 `15f347ee`에는 missing path `WORKFLOW001`이 발생했다. 적용은
  HTTP 200, `applied=false`였고 source hash와 프로젝트 revision이 유지됐다. 이는 오류 진단이
  남은 AI 원문이 compiler gate를 우회하지 못한다는 실제 검수 결과다.
- 실제 모바일 DOM 390×844에서 실패 메시지는 입력 화면 안에 표시됐고 같은 버튼의 성공 결과는
  완료 화면으로 이동했으며 입력값이 유지됐다. handoff snapshot 3은 source hash
  `5bfd722a55…`, 결정 2개, 원문, IA·읽기 명세를 같은 버전에 담았다.
- 이전 작업 `359ad62e`는 compiler error가 0건이어도 lookup 의미를 발명해 반려했던 역사적
  사례다. 최신 프롬프트의 위 검수가 이를 대체한다.
- 로컬 커밋과 wheel은 정식 compiler 릴리스가 아니다. dahaze 의존성 핀 승격과 production
  API·worker 배포도 하지 않았다.

## 계약 검수의 시간순 기록

아래 표와 설명은 계약을 확장하면서 남긴 역사적 검수 기록이다. `아직 필요한 범위`,
`추가 구현 중`, 특정 과거 커밋·wheel에 대한 표현은 당시 상태를 뜻한다. 현재 완료·미완료
경계는 위 `CURRENT` 절을 따른다.

초기 2026-09-23 검수에서 dahaze 설치 버전은 0.1.2였고, 새 업무 검증은 rspdl-core 작업
커밋 `1bd4462`의 로컬 CLI로, 구조화 편집은 `2eb7d59`의 로컬 wheel로 확인했다. 해당 wheel의
패키지 메타데이터 0.1.3은 정식 배포물과 동일하다는 뜻이 아니었다.

| 계약 | 당시 확인한 범위 | 당시 남은 범위 |
|---|---|---|
| IA·화면·경로 | 선언된 화면, 레이아웃, 버튼과 경로를 IR로 제공 | 환경별 의미·역할 연결의 확장 검증 |
| 업무 완료 데이터 | 시작, 초기 데이터 전제, 제출 버튼에 연결된 입력 확보, 완료 요구와 모든 경로 분석 | 조회 성공·계산·생성에 의한 확보 계약 |
| 업무 진단 | 필수 데이터 누락, 완료 도달 불가, 잘못된 확보 출발점, 배치되지 않은 입력 | 행동 결과별 조건과 실패 복구 의무 |
| 순환 흐름 | 유한한 데이터 확보 집합의 고정점 분석 | 데이터 삭제·상태 변화가 섞인 경로의 의미 |
| 검증 미지원 | 도달 가능한 삭제/조건부 생산의 영향은 구조화된 unknown 경고 | unknown을 해소하는 제한된 상태·조건 계약 |
| 요소 식별 | 모든 레이아웃 종류의 선택적 명시 ID, 중첩 트리 내 중복 검사, 삭제 하위 요소 tombstone | 기존 ID 없는 요소의 사용자가 검토하는 전환 |
| 구조화 편집 | 삽입·삭제·이동·속성 변경·경로 연결/해제 후보와 컴파일 결과, 정확한 원문 hash 검사. UI 문구 변경→초안 검토→명시적 적용을 실제 브라우저로 확인 | 결과별 연결/해제와 행동 연결 해제의 새 계약 통합 |
| 화면 체험 | 선언된 경로를 사용자가 선택, 입력값 유지 | typed 성공·실패·같은 화면 메시지·팝업 처리 |
| 여러 문서 | 파일별 컴파일과 workspace 중복/참조 검사 | 다른 파일의 모델을 한국어 이름으로 참조하는 linking 계약 |

`초기 데이터`는 사용자가 선언한 업무 시작 전제다. 컴파일러가 조회나 외부 시스템 호출의
성공을 입증했다는 뜻이 아니다. 경로 설명은 자유 서술이며 조건식으로 실행하지 않는다.
같은 버튼에서 여러 경로가 나가면 명시된 조건 계약이 생기기 전까지 가능한 대안으로 다룬다.

dahaze는 compiler가 제공한 진단과 지원 범위를 표시한다. 문서 목록을 함께 보낸 사실만으로
공통 모델의 파일 간 linking이 지원된다고 표시하거나, 화면에 들어왔다는 이유만으로 데이터가
확보됐다고 판정하지 않는다. 정식 연결 시에는 기존 코퍼스 재컴파일과 배포 플랫폼 wheel,
프롬프트·출력 문법·IR 소비 코드를 함께 검사한다.

당시 추가 구현 중이던 행동 결과 계약은 성공·실패·취소·시간 초과, 같은 화면의 상태·메시지·
팝업·로딩 처리, 조회 결과·계산·생산자의 명시적 데이터 출처를 다뤘다. 작업 CLI에서 성공
조회가 섞인 120개 경로를 독립 상태 탐색과 대조했으며,
선택 데이터 조회와 확실한 누락 우회가 함께 있으면 우회 경로를 진단하는 것도 확인했다.

진단 경로 탐색에서 검사 대상과 무관한 확보 필드까지 상태에 넣어 지수적으로 느려지는
문제를 발견했다. 필요한 필드·선행 필드로 추적 범위를 제한한 작업 CLI는 동일한 16개 분기
사례를 약 1.106초에서 0.007초로 줄였고, 96개 분기·98개 화면의 합성 사례를 약 0.020초에
검사했다. 로컬 개발 빌드의 특정 입력 측정이며 모든 명세의 처리 시간 보장은 아니다.
