- 최종 검수 커밋 `b920651`에서 전체 하네스가 통과했다: API 215개 통과·3개 skip,
  web 201개, editor 46개. 타입 검사, lint, build, 아키텍처 경계, OpenAPI drift/codegen
  검사도 통과했다.

### 실제 AI 종단간 검수 완료 — 로컬

- 최신 분리 프롬프트와 `gpt-5.4-mini`로 인터뷰→정책 채택→재생성→검토→명시적 적용을
  실제 실행했다. 첫 생성 작업 `233eca`의 후보 `9aa9`에는 compiler가 중복 ID `LINK003`과
  중복 operation `DATA004`를 보고했다. 오류 후보를 확정 원문으로 취급하지 않고 인터뷰
  `3732`로 manual-only 범위와 제거 방식을 설명받았다.
- AI 정책 제안 `2893`을 사용자가 명시적으로 채택했다. 채택 뒤에도 AI가 제안한 정책 본문과
  근거, 사용자의 판단 이유가 각각 보존됐다.
- 해당 오류 후보를 기준으로 실행한 생성 작업 `ce733b15`는 약 13초 만에 성공했다. 새 초안
  `a618e2d2`는 compiler 진단 0건이었고 이전 반려 사유였던 invented lookup이 없었다. 컴파일
  결과에는 IA, 화면 2개, 결과 2개, 경로 2개와 manual workflow가 포함됐다.
- UI에서 이 초안을 명시적으로 적용한 요청은 HTTP 200과 `applied=true`를 반환했고 프로젝트는
  revision 1이 됐다. 실제 모바일 DOM은 390×844였으며 같은 입력 화면 안에 실패 메시지가
  표시되고, 같은 버튼의 성공 결과는 완료 화면으로 이동하며, 입력값은 결과 전환 뒤에도 유지됐다.
- 적용 원문에서 acquisition을 제거한 반례 `15f347ee`에는 compiler가 missing path
  `WORKFLOW001`을 보고했다. 적용 요청은 HTTP 200과 `applied=false`를 반환했고 프로젝트
  revision과 source hash는 바뀌지 않았다.
- UI에서 만든 handoff snapshot 3은 source hash `5bfd722a55…`와 결정 2개, 적용 원문,
  IA·읽기 명세를 같은 버전에 담았다.
- 이전 작업 `359ad62e`는 compiler error 0건이어도 원문에 없는 lookup을 발명해 반려했던
  역사적 실패 사례다. 최신 프롬프트의 위 종단간 검수가 이 결과를 대체한다.

## 검수 기준

### 원문과 검증

- 의미 규칙은 compiler 소유이며 dahaze에서 YAML을 해석하거나 진단을 합성하지 않는다.
- 원문 hash·runtime·wire version이 다른 결과를 같은 검증으로 표시하지 않는다.
- 경로 설명을 실행 조건으로 해석하지 않는다. 여러 경로는 사용자가 명시적으로 선택한다.
- 입력 조작 선언만으로 화면 입력칸이 있다고 판정하지 않는다.
- 조회 선언만으로 필요한 record가 존재한다고 판정하지 않는다.
- 업무의 완료 지점에 도착한 이후의 입력을 이전 경로의 확보 근거로 사용하지 않는다.
- 삭제·지원하지 않는 상태 변화·solver unknown을 검증 성공으로 근사하지 않는다.

### 저장과 복원

- 대화·미정·오류 초안 보관과 확정 명세 적용은 별개다.
- 기존 문서 편집 경로도 프로젝트 버전 경쟁 검사에 포함한다.
- 오류 진단이 있는 apply는 미적용 상태와 compiler result를 반환하며 HTTP 의미 오류로 바꾸지 않는다.
- warning/info만으로 적용을 막지 않는다. 알 수 없는 결과 형식을 통과시키지 않는다.
- 여러 문서 적용은 전부 성공하거나 전부 롤백한다.
- 첫 적용 전 기준 상태도 복원 가능해야 한다.
- 디자인/대화 변경 경쟁과 원문 변경 경쟁을 구분하고 둘 다 유실을 방지한다.
- 전달본은 전체 프로젝트의 특정 버전이며 이후 편집으로 바뀌지 않는다.

### 화면

- 의미 변경은 제안→컴파일→검토→적용을 거친다.
- 디자인 위치·크기는 RSPDL 밖에 보관한다.
- 기존 요소의 배치를 인덱스만으로 새 원문에 잘못 연결하지 않는다.
- 가상 데이터는 명세 또는 실데이터로 표시하지 않는다.
- 미정 요소와 미지원 동작은 실행할 수 없고 원인을 표시한다.
- 화면·요소의 명세 탐색은 source path와 stable ID를 유지한다.
- 개발 전달은 화면·다운로드·MCP가 동일한 버전과 권한을 사용한다.

## 주 에이전트 독립 검수

- compiler `2eb7d59`의 격리된 Python wheel로 8종 요소의 삽입→삭제 왕복을 확인했다.
  각 편집 응답의 후보 hash와 독립 compile 결과가 일치했다. 외부 모듈 ID, 동일 값 변경,
  요소 종류와 맞지 않는 속성 변경, 부모를 자손 안으로 이동하는 4종 요청은 거절됐고,
  컨테이너 삭제는 모든 하위 stable ID를 tombstone으로 돌려줬다. 한글·비 BMP 문자·CRLF·
  정규화 형태가 다른 문자열의 hash를 표준 SHA-256 구현과 대조했다.
- compiler CLI와 별도로 구현한 경로 탐색 기준으로 비순환 그래프 96개, 순환을 포함한
  방향 그래프 160개의 완료 시점 데이터 확보 결과를 대조했다. 모두 일치했다.
  이 검사는 명시된 입력 확보·초기 데이터·도달 가능성에 한정하며 조건부 생성, 조회 성공,
  삭제 이후 데이터 상태까지 검증했다는 뜻은 아니다.
- 존재하지 않는 시작 화면·필수 필드와 빈 완료 집합을 각각 컴파일했고, 세 경우 모두
  오류 진단을 확인했다.
- 서로 격리된 프로세스에서 설치된 0.1.2와 compiler 작업 커밋 `1bd4462`의 로컬 wheel로
  기존 코퍼스·항공 예제 9개를 재컴파일했다. 컴파일 가능 여부와 진단 rule/severity 차이는
  없었고 wire schema는 모두 1이었다. 실제 운영 DB 전체나 이후 C1 변경의 승격 검증은 아니다.
- 서로 다른 화면의 동일 버튼 ID가 연결을 공유하던 문제와 동일 요소 경로가 디자인을
  공유하던 문제를 반려했다. 담당 에이전트가 회귀 테스트를 추가했으며 실제 화면 검수는
  통합 후 진행한다.
- 적용·복원 검수에서 독립적인 스냅샷 버전, 디자인 변경 경쟁 검사, 실제 저장 문서 ID,
  복원 직전 상태 보관, 읽기 조회의 불필요한 쓰기 잠금 제거를 요청했다.
- 저장 계약은 [ADR-0007](../adr/0007-planning-workspace-versions.md)에 기록했다.
- 실제 HTTP 요청으로 원문 변경 없이 디자인 A/B를 각각 캡처하고, 디자인 C 상태에서
  A로 복원했다. C는 복원 전 기준으로 남았고 기존 B 전달본은 변하지 않았다.
  이전 기획 리비전으로 다시 쓰는 요청은 409로 거절됐다.
- `6f26b84` 기반 기획 API·컴파일러 편집 테스트 21개를 주 에이전트의 별도 DB에서 실행해
  통과했다. 실제 로컬 compiler 연결은 위의 격리 wheel 검수와 구분하며 운영 배포 검증은 아니다.
- `983b393`의 메타데이터 버전·ID 기반 결정 해결을 포함한 같은 독립 검수 범위는 25개를 통과했다.
- 로컬 C1 wheel `2eb7d59`를 별도 API 환경과 아티팩트 전용 DB에 연결해 실제 HTTP 편집 흐름을
  확인했다. 후보 생성은 원문을 저장하지 않았고, 의미 오류 후보도 초안으로 남았다. 오류 초안
  적용은 HTTP 200의 미적용 결과를 반환했고, 정상 후보는 원문과 정확히 같은 내용으로 적용됐다.
  같은 기준 버전으로 재적용하는 요청은 409였다. 다른 compiler 빌드와 캐시를 공유하지 않는다.
- 실제 브라우저에서 배치 이동→저장→실행 취소→저장을 수행했고, 두 저장 요청에 동일 위치가
  전송되는 결함을 재현했다. 저장된 위치와 로컬 차이를 병합하면서 취소가 무효화되는 문제로
  반려했다. `1da67f3`에서 같은 브라우저 조작을 반복해 저장 후 취소가 이전 좌표를 복원함을
  확인했다. 첫 위치 지정의 제거와 자동 저장 중 추가 편집은 후속 통합 검수 대상이다.
- 결정 채택이 기존 미결 항목을 갱신하지 않고 새 항목을 추가하는 문제, 메타데이터 저장 이력과
  프로젝트 복원이 분리되어 화면에 오래된 값이 남는 문제를 찾아 원자적 ID 기반 해결과 일관된
  메타데이터 버전 기록을 요청했다.
- 브라우저에서 디자인 상태를 포함한 전달본 3을 생성하고 JSON을 다운로드했다. 별도의 실제
  MCP HTTP `get_project_handoff` 요청 결과와 다운로드 JSON 전체를 비교해 동일함을 확인했다.
  검수용 계정·합성 100화면 프로젝트·설치 compiler 0.1.2를 사용했다.
- 실제 브라우저에서 버튼 이벤트가 그래프의 화면 선택으로 덮여 이동이 취소되는 결함을
  재현해 반려했다. 수정 후 단계 0→1→2 이동과 입력값 유지, 모바일 390×844 전환,
  체험 모드에서 미니맵 제거를 확인했다.
- 100개 화면의 단순 합성 프로젝트를 1280×720 로컬 개발 브라우저에서 측정했다.
  휠 조작 30회 중 수집한 120개 프레임 간격의 p95는 약 16.8ms, 최댓값은 50ms였다.
  실제 렌더된 가시 노드는 2개였다. 복잡한 목록·정책과 다중 환경의 배포 성능을 보장하는
  수치는 아니며, 이 시점에는 최종 통합 성능 검사를 별도 항목으로 남겼다.

이하 내용은 발견→수정→재검수의 시간순 기록이다. 이미 후속 커밋과 검수로 해결된 결함도
남겨 두며, 현재 미해결 결함 목록으로 사용하지 않는다.

## 통합 검수 당시 추가로 확인한 항목

아래 목록은 후속 검수를 이끌기 위해 작성한 당시의 open item이다. 뒤의 후속 브라우저 기록과
문서 맨 위 `CURRENT` 절이 최신 상태를 덮어쓴다.

- 배치 자동 저장의 기준 버전은 편집 시작 시점과 연결해야 한다. 외부 응답을 받았다는
  이유만으로 오래된 편집 내용을 최신 버전의 값처럼 저장해서는 안 된다. 저장 중 환경
  전환, 후속 편집, 첫 위치 지정 취소, 페이지 이동 후 미저장 내용 복원을 함께 검수한다.
- 환경·샘플 편집은 충돌 안내와 실제 저장 차단이 일치해야 한다. 저장 요청 뒤 추가한
  편집 내용을 앞선 응답이 저장 완료로 처리하지 않아야 한다.
- 정책이 없는 모델도 샘플 편집 대상이다. 정책에 연결된 필드 목록을 전체 모델 목록으로
  사용하는 구현은 반려했다. 읽기용 명세의 생성 근거 역시 실제 compiler의
  `conditional_productions[].field_producers` 구조를 기준으로 검수한다.
- 결과별 데이터 확보를 추가한 compiler는 진단의 반례 경로도 같은 확보 규칙으로
  계산해야 한다. 관계없는 분기의 불확실성이 확실한 누락 경로를 감추지 않아야 한다.
- 전달본 비교는 원문 외에 문서 정보와 기획 결정의 변경도 확인할 수 있어야 한다.
  긴 읽기 전용 와이어프레임은 편집을 막아도 스크롤은 가능해야 한다.

위 항목 자체는 당시 수정 요청 또는 검수 진행 상태였으며, 통과 기록으로 취급하지 않는다.

### 후속 브라우저 확인 (`4d23af8`, `70bfcc7`)

- 정책이 없는 상품 모델의 샘플 행을 생성·저장하고, 실제 화면 목록에 표시됨을 확인했다.
  체험에서 행을 선택하면 연결된 입력칸에 같은 값이 표시됐다.
- 화면 제목 변경을 UI에서 요청하고, 컴파일된 변경안의 이전/이후 원문을 검토한 뒤
  명시적으로 적용했다. 화면으로 돌아와 변경한 제목이 렌더링됨을 확인했다.
- 첫 화면 위치 지정의 자동 저장과 실행 취소를 실제 요청으로 확인했다. 실행 취소 후
  저장된 `positions`는 빈 객체였으며, 두 요청은 모두 성공했다.
- 환경 해상도 3840×2160을 저장하고 전달본에서도 같은 수치를 확인했다. 선택한 화면이
  없는 환경은 전달본에서 빈 상태로 보였고, 전체 환경으로 전환하면 샘플을 포함한 화면이
  다시 보였다.
- 새 브라우저 세션에서 체험 입력값을 페이지 이동 후 복원하지 못하는 결함과, 빈 환경을
  선택하면 화면 흐름의 환경 선택기까지 사라지는 결함을 재현했다. 후속 UI 담당자에게
  재현 절차와 함께 전달했으며 당시에는 통과 항목이 아니었다.

### 결과 계약·항공 사례 통합 검수 (`533a542`, `3100e7a`)

- 컴파일러의 canonical 결과 ID로 경로를 해제하지 못하고, 연결 생성 시 원문에 맞지 않는
  화면 참조를 쓰는 결함을 실제 HTTP에서 재현했다. core `533a542` 수정 후 별도 wheel,

  실패 handler를 없앤 후보에는 `RSPDL-OUTCOME-010`이 남고 확정 원문은 변경되지 않았다.

  `93e933bdf4c61fb670addcce02d5ca9ec864d2e7ff81da43a145f74b15062445`다.
  패키지 메타데이터의 0.1.3은 공식 릴리스와 동일한 바이너리라는 뜻이 아니다.
