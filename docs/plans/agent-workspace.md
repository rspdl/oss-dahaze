# 에이전트 작업공간: 에디터 + AI 대화

결정 근거: [ADR-0008](../adr/0008-working-tree-commits-and-locks.md), [ADR-0005](../adr/0005-mcp-and-llm-authoring.md).

## 목표

- 기획자는 Claude Code를 쓰듯 대화로 문서를 만들고 고친다. 가운데에는 에디터가 있어서
  파일 내용을 바로 보고 직접 고칠 수 있다.
- 앱 안의 AI와 외부 MCP 클라이언트는 **같은 도구 세트**로 같은 작업 트리를 다룬다.
- 변경은 도구 호출 단위로 보이고, 사람이 고른 파일만 commit으로 이력이 된다.
- 기존 인터뷰 기능은 대화 기능으로 합친다. 결정·보류·제안 같은 구조화 상태는 두지 않는다.

## 저장 모델

SVN과 같은 구조다. 프로젝트마다 **공유 작업 트리 하나**가 있고, 모든 멤버와 모든 세션이
같이 쓴다.

| 개념 | 설명 |
|---|---|
| 작업 트리 | 폴더와 문서의 현재 상태. AI 도구는 바로 쓰고, 사람은 에디터의 저장 버튼으로 쓴다 |
| commit | 사람이나 AI가 파일을 골라 만드는 이력 한 점. 메시지 필수 |
| 잠금 | AI가 쓰는 파일에 거는 파일 단위 잠금 |

- 오류 진단이 남은 원문도 작업 트리에 저장하고 commit할 수 있다. 진단은 compile에서 본다.
- 폴더는 엔티티로 둔다. 빈 폴더를 유지해야 `mkdir`가 의미를 가진다.
- `mv`는 문서 ID를 유지한다. 이름을 바꿔도 이력이 이어진다.
- commit에는 바뀐 파일마다 변경 종류(add/modify/delete/move), 옛 경로·새 경로, diff,
  **바뀐 뒤의 전문**을 남긴다. 전문을 함께 두면 역패치 하나가 손상되어도 그 이전 이력을
  잃지 않는다. 진단과 컴파일러 버전은 남기지 않는다.
- commit이 기존 문서 리비전(`document_revisions`)과 전달본 스냅샷을 대체한다. 이관하지 않는다.
- 작업 트리에서 commit 전 변경을 버리는 기능은 이번 범위에 없다.

## 잠금

- AI가 파일에 처음 쓸 때(`add`·`edit`·`mv`·`delete`) 그 파일의 잠금을 얻는다. 폴더를
  `mv`·`delete`하면 안의 파일을 전부 잠근다. 읽기 도구는 잠금을 얻지 않는다.
- 앱 AI의 잠금은 AI가 턴을 끝내고 사용자 응답을 기다리는 시점에 모두 풀린다. 강제 종료,
  오류 종료에서도 같다.
- MCP 클라이언트는 `unlock` 도구로 푼다. 호출을 잊거나 연결이 끊기는 경우를 위해
  타임아웃도 적용한다.
- MCP 전송은 stateless라 세션 ID가 없다. MCP 잠금 보유자는 토큰 사용자 단위(`mcp:<user_id>`)다.
  같은 사용자의 MCP 클라이언트끼리는 잠금을 공유하고, 다른 사용자의 잠금은 풀 수 없다.
- 잠금은 그 세션의 마지막 쓰기부터 10분이 지나면 만료된다. 만료되면 잠금을 풀고 그 AI 작업을
  중단한다. 사용자 승인을 기다리는 동안은 시간을 세지 않는다.
- 다른 세션이 잠근 파일에 쓰려 하면 도구가 잠금 보유자와 함께 오류를 돌려준다. AI는
  사용자에게 알리고 턴을 끝낸다. 턴이 끝나면 자기 잠금도 풀리므로 교착이 생기지 않는다.
- 잠긴 파일은 에디터에서 읽기 전용이 되고, 사람의 저장과 다른 사람의 commit 포함이
  막힌다. 사람이 저장하지 않은 입력은 AI가 쓰면 사라진다.

## 도구

앱 AI와 MCP가 같은 `application/` 유스케이스를 부른다. 경로는 프로젝트 루트 기준 `/`로
시작한다.

### 읽기

| 도구 | 입력 | 출력 |
|---|---|---|
| `ls` | `path?` (기본 `/`) | 폴더·파일 트리. 파일마다 commit 안 된 변경 여부, 잠금 보유자 |
| `read` | `path` | 문서 전문과 줄 수 |
| `search` | `query`, `kind?` | 일치한 심볼 목록, 심볼을 읽지 못한 파일 목록 |
| `grep` | `pattern`, `path_glob?` | `path:line: 줄 내용` 목록. 상한 200개, 넘으면 `truncated`. 정규식은 RE2 |
| `compile` | 없음 | 파일별 진단 |

**search**

- 작업 트리 전체를 컴파일한 IR에서 찾는다. 컴파일 캐시(ADR-0003)를 그대로 쓴다.
- `query`는 심볼 ID와 이름에 부분 일치한다(대소문자 무시). `kind`는 IR의 컬렉션 경로
  (`models`, `models.fields`, `roles`, `actions`, `policies`, `screens` …)로 거른다.
- 심볼은 IR에서 `id`와 `span`을 가진 노드 전부다. 종류 목록을 dahaze가 따로 정의하지 않으므로
  rspdl이 종류를 추가해도 검색 코드를 고치지 않는다. 읽는 코드는 `infrastructure/rspdl/indexer.py`에 있다.
- 결과 항목: `id`, `kind`, `name`(있을 때), `path`, 시작·끝 줄.
- 구문 오류로 `module`이 비는 파일은 `unparsed: [{path, error_count}]`로 함께 돌려준다.
  AI가 "심볼이 없다"와 "읽지 못했다"를 구분하게 하려는 것이다.
- policy·constraint는 이름이 없고 ID가 원문 hash라 편집하면 바뀔 수 있다. 이 둘은 연결된
  model·role·action을 먼저 찾고, 그 결과의 연결 ID로 찾는다.
- 텍스트 일치는 search에 섞지 않는다. 텍스트는 `grep`만 다룬다.

**compile**

- 진단마다 `path`, 시작·끝 `line:col`, `severity`, `rule_id`, `message_key`, `arguments`.
- IR span은 **UTF-8 byte 오프셋**이다(rspdl 0.1.4에서 확인). 줄·열 변환은 byte 기준으로 한다.
- IR 전문은 돌려주지 않는다.

### 쓰기

| 도구 | 입력 | 잠금 |
|---|---|---|
| `mkdir` | `parent`, `name` | 없음 |
| `add` | `parent`, `name`, `content` | 새 파일 |
| `edit` | `path`, `content` (전문 교체) | 대상 파일 |
| `mv` | `from`, `to` | 대상 파일, 폴더면 안의 파일 전부 |
| `delete` | `path` | 대상 파일, 폴더면 안의 파일 전부. 비어 있지 않은 폴더는 사용자 승인 뒤 재귀 삭제 |
| `commit` | `paths`, `message` | 다른 세션이 잠근 파일이 있으면 거부 |
| `unlock` | `paths?` | MCP 전용. 생략하면 자기 잠금 전부 |

- 쓰기 도구는 일반 function tool이다. `content`에 문법 제약을 걸지 않고, RSPDL 문법은 시스템
  프롬프트의 맥락으로 알려준다. 구문 오류는 `compile` 진단으로 드러난다(ADR-0005).
- 쓰기 도구는 작업 트리를 바꾼 뒤 결과에 변경 전후 줄 수 차이를 싣는다. 컴파일은 자동으로
  돌리지 않는다. AI가 `compile`을 부른다.
- 비어 있지 않은 폴더를 지우려 하면 AI 턴이 멈추고 사용자에게 재귀 삭제 승인을 묻는다.
  사용자 설정으로 이 승인을 생략할 수 있다. 승인을 기다리는 동안 잠금은 유지하고 10분 타이머는
  멈춘다. 거절하면 도구가 거절 결과를 돌려주고 AI가 턴을 이어 간다.
- `commit`에 이동한 파일을 넣으면 옛 경로와 새 경로가 한 단위로 들어간다.

### fetch

`fetch(id, owner_id?)` 는 심볼 선언의 원문 구간과, 그 심볼을 가리키는 심볼(`referenced_by`)·그
심볼이 가리키는 심볼(`references`)을 돌려준다. 연결은 컴파일 결과의 `references`
([rspdl-core#41](https://github.com/rspdl/rspdl-core/issues/41), PR #42)에서 읽는다. locator 의
`kind` 는 search 의 kind 와 같은 IR 컬렉션 경로다. 화면 요소처럼 소속마다 따로 있는 local ID 는
`owner_id` 로 고른다.

`references` 를 주지 않는 컴파일러(PyPI 0.1.4)에서는 원문만 돌려주고 `references_supported: false`
로 표시한다. #42 가 들어간 버전이 PyPI 에 나오면 `upgrade-rspdl` 절차로 핀을 올린다.

### 파일 구성

AI 작업자는 문서를 한 파일에 모으지 않고 도메인 영역 폴더 아래 관심사별 파일로 나눈다. 규칙과
쓰기 전 판단 절차는 `prompts/agent_system_ko.md` 의 tree-layout 구간에 있고, MCP 서버
instructions 가 같은 구간을 가져다 쓴다.

rspdl 0.1.4 에서 컴파일로 확인한 제약이 나누는 방식을 정한다(`tests/test_agent_prompts.py`).

- 파일 하나가 모듈 하나다. 백틱 참조는 같은 파일의 선언만 찾고, 다른 파일의 모델을 가리키면
  `RSPDL-KO-REF-001` 이 난다. 같은 모듈 ID 를 두 파일에 써도 참조는 이어지지 않는다.
- 두 파일이 같은 모듈 ID 를 쓰면 `RSPDL-LINK-001` 이 난다.

그래서 모델·정책·화면 같은 선언 종류별 파일 분리는 하지 않는다. 종류별 구분은 파일 안의 선언
순서로 하고, 파일은 서로 참조하지 않는 관심사 단위로 나눈다. 컴파일러가 파일 사이 참조를
지원하면 이 규칙을 다시 정한다.

## 에이전트 실행

- 한 턴에 도구 호출은 최대 100회다. 닿으면 "계속할까요?"로 턴을 끝내고, 사용자가 답하면
  이어 간다.
- 턴은 지금의 PostgreSQL 작업 큐 + worker + lease로 실행한다. 도구 호출과 응답은
  이벤트 테이블에 기록하고 웹은 SSE로 받는다.
- 도구 호출마다 호출 전후 원문을 대화 기록에 남긴다. 채팅 카드에서 그 호출의 diff를 연다.
- 대화는 Claude Code처럼 세션 단위다. 새 세션을 열거나 지난 세션을 이어 간다.

### 구현 (3단계)

- 턴 상태는 `agent_turns`, 대화 기록은 `agent_items`(세션 안 순번 `seq`)에 있다. 턴은 이 기록만
  읽고 이어서 실행한다. worker 가 도구 호출 도중 멈췄으면, 다음 worker 가 결과 없는 호출에
  "결과를 알 수 없다" 결과를 붙이고 계속한다.
- 세션 하나에 진행 중인 턴은 하나다(부분 유니크 인덱스). 같은 `request_id` 로 다시 보내면
  메시지를 한 번만 기록한다.
- 도구 호출은 하나마다 커밋한다. 대화 항목을 기록하는 트랜잭션에서 lease 를 연장하고, lease 를
  잃은 worker 는 아무것도 기록하지 않고 멈춘다.
- 잠금 충돌이 나면 다음 모델 호출은 도구 선택을 막고(`tool_choice: none`) 답변만 받는다.
- 비어 있지 않은 폴더 삭제는 턴을 `awaiting_approval` 로 멈춘다. 같은 응답의 뒤쪽 도구 호출은
  실행하지 않았다는 결과로 채운다. 승인하면 보유자 잠금의 마지막 쓰기 시각을 현재로 바꾸고
  재귀 삭제를 실행한 뒤 이어 간다. 거절하면 거절 결과를 모델에게 준다.
- 잠금 만료는 모델 호출 전에 확인한다. 모델 호출 하나가 오래 걸려 10분을 넘기면 그 호출이 끝난
  뒤 멈춘다.
- 모델 입력은 매번 `agent_items` 에서 만든다. 도구 결과의 `changes`(파일 전후 원문)는 화면용이라
  모델 입력에서 뺀다. 시스템 프롬프트는 `prompts/agent_system_ko.md` + 기존 문법 요약·예시 +
  EBNF 스냅샷이다.
- LangChain(LangGraph)은 도입하지 않았다. 루프 본체(`AgentTurnRunner`)는 도구 실행기를 빼고
  350줄이고, 잠금·승인·lease 처리는 프레임워크를 써도 직접 작성해야 하는 부분이다.

## 실시간 반영

프로젝트 이벤트 스트림(SSE) 하나로 작업 트리 변경, 잠금 획득·해제, commit, 세션 이벤트를
보낸다. 이벤트 종류는 `tree.changed`, `locks.released`, `commit.created`, `agent.item`,
`agent.text_delta`, `agent.turn` 이다. `agent.item` 은 `seq` 만 싣고, 화면은 그 이후 항목을
`list_agent_items` 로 읽는다.

- SSE: `GET /api/projects/{id}/events/stream`. 생성 클라이언트로 부를 수 없어 OpenAPI 에서 뺐다.
  같은 이벤트를 `GET /api/projects/{id}/events`(JSON)로도 주며, 타입은 여기서 생성된다.
- SSE 는 요청 세션을 쓰지 않는다. 요청 세션은 응답이 끝날 때까지 DB 연결을 잡는다. 인증·권한
  확인과 조회마다 짧은 세션을 연다.
- API 프로세스마다 `LISTEN` 연결 하나가 알림을 받아 구독 중인 SSE 요청을 깨운다. 알림에는
  프로젝트 ID 만 싣고 내용은 DB 에서 읽으므로, 알림을 놓쳐도 다음 조회에서 빠짐없이 받는다.
  `LISTEN` 에 실패하면 2초 간격 조회로 동작한다. MCP 클라이언트가 바꾼 파일도 같은 스트림으로 화면에 반영된다. 변경 주체 구분은
화면에 따로 두지 않고 commit 기록에서 본다.

## 화면

```
┌────────────┬─────────────────────────────┬──────────────────┐
│ 프로젝트 ▾ │ [문서] [IA]   ← 뷰 선택 바  │ AI 대화          │
│────────────│                             │ 세션 ▾  + 새 세션│
│ 파일 트리  │  문서: 선택한 파일 원문,    │                  │
│ ▸ 주문/    │   commit diff, 호출 diff    │ 사용자 메시지    │
│   결제.rs… │  IA: 정보구조 → 화면 →      │ ⏺ Search("재고") │
│   🔒 배송… │   화면 흐름 계층            │   → 3건          │
│            │                             │ ⏺ Edit(/주문…)   │
│ 변경 3     │                     [저장]  │   +12 −3   ← 클릭│
│ ☑ 결제     │                             │ ⏺ Compile        │
│ [commit]   │                             │   → 오류 1       │
│ 이력       │                             │ 입력창           │
└────────────┴─────────────────────────────┴──────────────────┘
```

- 왼쪽은 앱 내비게이션 기둥이다. 프로젝트 안에서는 프로젝트 전환기 아래에 파일 트리와 변경·이력이
  들어간다. 작업공간이 `AppShell` 의 `sidebar` 슬롯으로 넘긴다. 기둥을 접으면 트리를 숨기고 펼치기
  버튼만 남는다. 좁은 화면에서는 서랍으로 열리고, 가운데에 보일 것을 고르면 닫힌다.
- 대화가 중심이고, 가운데는 사용자가 고른 것을 보여준다. AI가 파일을 바꿔도
  가운데는 자동으로 전환하지 않는다.
- 채팅의 도구 카드를 누르면 가운데에 그 호출의 diff가 열린다.
- 왼쪽 아래에 commit 안 된 변경 목록이 있고, 파일을 골라 메시지와 함께 commit한다.
  commit 이력을 누르면 가운데에 그 commit의 diff가 열린다.
- 가운데 위쪽의 뷰 선택 바가 같은 작업 트리를 어떤 뷰로 볼지 고른다. 뷰 목록과 주소 조각은
  `features/navigation/views.ts` 의 `PROJECT_VIEWS` 하나가 원본이다(`/projects/{id}/documents`,
  `/projects/{id}/ia`, `/projects/{id}/wireframe`). 모든 뷰가 `app/projects/[projectId]/layout.tsx` 를 공유하므로 뷰를 바꿔도
  트리·대화·이벤트 스트림이 다시 마운트되지 않는다. 예전 `/workspace` 주소는 기본 뷰로 보낸다.
  - **문서**: 파일 에디터, commit diff, 도구 호출 diff. 다른 뷰에서 파일·commit·도구 카드를 고르면
    이 뷰로 옮긴다.
  - **IA**: 작업 트리를 컴파일한 결과의 `information_architecture`·`screen_categories`·`screens`·
    `screen_paths` 를 파일별로 묶어 분류 → 화면 → 화면 흐름 순서로 보여준다. 항목을 누르면 그 줄을
    문서 뷰로 연다. `compile_tree` 와 `search` 는 IR 을 주지 않고 검색 결과에는 `parent_id`·분류
    배정이 없어서, 작업 트리 파일을 읽어 `compile_workspace` 에 넘긴다. 저장한 원문 기준이고, 파일
    수만큼 `read_tree_file` 을 부른다. 트리 크기가 커지면 IR 을 주는 트리 엔드포인트가 필요하다.
  - **와이어프레임**: 같은 컴파일 결과의 `screens`·`screen_layouts`·`screen_paths` 로 화면을 회색
    목업 카드로 그리고 경로로 잇는다(React Flow). 왼쪽 열로 돌아가는 경로는 카드 아래로 돈다.
    카드를 더블클릭하면 Column·Row·Box 배치 트리 편집기가 열리고 Compose 코드도 보여준다.
    기획 요소는 선언된 영역 안에서만 옮기고, 더하기·지우기는 문서를 고친다("원문 열기").
    보드 위치와 배치 트리는 문서 옆 `<문서>.wireframe.json` 에 자동 저장한다(편집이 멈추고 0.7초 뒤).
    바뀐 화면 항목만 고쳐 쓰므로, 오류로 컴파일러가 IR 을 내보내지 않은 문서의 배치는 지워지지
    않는다. rspdl 0.1.4 는 의미 오류가 하나라도 있으면 그 문서의 `module` 을 비워 보내므로, 그런
    문서는 "화면이 없다"가 아니라 "읽지 못한 문서"로 알린다. 정보구조에 담긴 화면은 앱 틀 안에
    그린다 — 최상위 분류가 앱, 그 아래 분류가 왼쪽 메뉴 묶음, 담긴 화면이 메뉴 항목이고, 위쪽에
    경로와 주소(분류·화면 id 끝 조각)를 보인다. 체험 모드에서는 메뉴로 화면을 옮기고, 버튼의 결과
    (도착 화면·메시지·팝업)를 골라 본다. 문서마다 UI 스타일(회색·shadcn/ui·Material 3·Bootstrap 5)을
    고르면 같은 구조를 그 프레임워크의 기본 모양으로 그리고, 편집기는 Compose 와 React·shadcn 코드를
    낸다. 히어로·기능 소개·CTA·카드 격자·통계·프로필·가격표·탭 섹션은 디자인 전용 노드 템플릿이고,
    디자인 전용 컴포넌트는 텍스트·버튼·이미지·배지·아바타·아이콘·통계·탭·진행 막대·검색칸이다.
    문서 요소는 모양만 고른다 — 목록은 표·카드·한 줄 목록, 버튼은 주·보조·텍스트·링크(`appearance`).
    요소는 선언된 영역 안에만 놓이고, 밖에 놓이면 고른 모양을 지닌 채 자기 영역 끝으로 돌아간다.
    편집기는 가운데 패널만 덮어 AI 대화를 열어 둔 채 편집한다. 메시지를 보낼 때 고른 화면을
    `context` 로 함께 보내고(화면 id·선언된 요소·영역 포함, 대화에는 화면 이름만 보인다), AI 는
    `wireframe` 도구로 그 화면 항목만 고친다. 도구는 저장 전에 요소가 선언된 영역에 있는지 컴파일
    결과로 확인해 틀리면 거부하고, AI·MCP 의 `edit` 은 다른 화면 항목을 지우면 거부된다(AI 가 파일
    전문을 다시 쓰다 다른 화면의 배치를 지운 일이 있었다).
    원본: `features/wireframe/`, `features/mockup/`.

## 기술 스택

기존 스택(FastAPI·SQLAlchemy·PostgreSQL·`openai`·`mcp`, Next·TanStack Query·CodeMirror)을
그대로 쓴다. 새로 정한 것:

- **실시간 전달**: worker가 `project_events`에 쓰고 PostgreSQL `NOTIFY`, API가 `LISTEN`해
  SSE로 보낸다. 재연결은 `Last-Event-ID`(seq) 이후를 DB에서 다시 보낸다. Redis는 들이지 않는다.
  AI 답변 델타는 약 100ms씩 묶어 이벤트 하나로 쓴다.
- **저장**: 폴더·문서는 전체 경로를 컬럼에 둔다(materialized path). commit diff는 `difflib`로
  서버에서 만든다. 잠금은 `INSERT … ON CONFLICT`로 원자적으로 잡는다.
- **대화 항목**은 dahaze DB에 저장하고 매 호출 입력을 다시 구성한다. 공급자의 대화 저장
  (`previous_response_id`)에 기대지 않는다.
- **에이전트 오케스트레이션**: 우선 직접 구현한다. 잠금·승인 대기·100회 상한·재개의 복잡도를
  보고 LangChain(LangGraph) 도입을 다시 판단한다.
- **grep 정규식 엔진**: `google-re2`. 선형 시간이라 사용자·AI 패턴이 워커 스레드를 멈추지 못한다.
  `import re2`는 `infrastructure/text/` 안에서만 한다.
- **도입 후보(미확정)**: `@codemirror/merge`(diff),
  `@headless-tree/react`(파일 트리), `react-markdown`+`remark-gfm`(채팅). 해당 단계에서 확정한다.

## 기존 데이터 초기화

새 이력은 빈 상태에서 시작한다. 문서, 리비전, 스냅샷, 기획 상태(결정·보류·제안·후보),
AI 작업과 대화 기록을 모두 지운다. 로컬과 운영 DB에 모두 적용한다. 사용자·프로젝트·멤버십은
남긴다.

운영 DB 초기화는 되돌릴 수 없다. 옛 데이터는 보존하지 않기로 해서 백업을 남기지 않는다. 릴리스
PR 본문에는 데이터 삭제를 명시한다.

마이그레이션 `37bb036a2b97`(drop documents planning and snapshots)이 옛 테이블 7개와
`projects.revision`·`source_hash`·`snapshot_version` 을 삭제한다. downgrade 는 빈 테이블만 다시
만든다. LLM 설정 환경변수는 `OPENAI_PLANNING_*` 에서 `OPENAI_REASONING_EFFORT`,
`OPENAI_AGENT_TIMEOUT_S` 로 바뀌었다. 배포 환경의 변수 이름도 함께 바꾼다.
